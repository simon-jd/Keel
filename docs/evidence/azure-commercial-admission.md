Only hashes and provenance enter the manifest; preparation makes no provider request. `--region` accepts only `eastus` (legacy default) or explicit `westus`, and binds both model metadata and the binding fingerprint. The endpoint is trusted operator configuration; it is not a region-discovery or deployment-success assertion.

After separately verifying a fresh official quote and saving its raw Retail meters, the controller can normalize a quote for `scripts/budget.py --ledger LEDGER reserve-commercial --quote QUOTE --binding BINDING`. Existing Decimal, flock, atomic replace, file/directory fsync and no-refund semantics remain. Only one reservation for the explicit `task8-bfcl-first10-seed0-azure-mini-v1` phase is permitted in a ledger; automatic extra reservations are unavailable. Generic reservations remain unchanged. A later bounded phase may use remaining headroom only after a separate controller policy ruling and review; this phase cannot reopen its allowance.

The eastus reservation can be amended only once, before any claim or attempt, using the trusted CLI `scripts/budget.py --ledger LEDGER rebind-commercial-unstarted --reservation EXISTING_ID --quote FRESH_WESTUS_QUOTE --binding NEW_WESTUS_BINDING`. This command is absent from HTTP and `commercial-rpc`. It operates under the same durable lock as claim and preserves the reservation ID, phase, estimate, all caps/counters, exact deployment and ordered request hashes. Each input/output Decimal price must equal the original separately, even if a different price pair could produce the same total estimate. The existing generic reservation path is unchanged; `reserve-commercial` still cannot create a new westus reservation. No extra reservation or refund is made.

Only endpoint, region, quote identity and independently validated fresh quote metadata may change. The ledger retains the complete original quote/binding under one `regional_rebinds` audit entry with UTC timestamp and the fixed subscription-region-policy reason. A westus claim requires that valid audit; manually changing a region field does not authorize dispatch. Generic, claimed, running/completed/failed, attempted, malformed and repeat transitions fail without writing. Claim and rebind are mutually exclusive across processes: a successful claim blocks rebind, and a successful rebind invalidates the old binding. Expired original quote evidence remains archived; only a fresh new quote can authorize the amendment or later dispatch.

One further operator-only exception can recover that claimed but **zero-attempt** westus reservation: `scripts/budget.py --ledger LEDGER recover-commercial-undispatched --reservation EXISTING_ID`. It is unavailable to HTTP, `commercial-rpc`, server startup or automatic retry/restart. The controller alone attests that the prior processes are stopped and that the archived diagnosis/GET/session establish the named pre-dispatch stop. Under the same durable lock as consume, the command independently requires the exact commercial phase, valid audited westus transition, running status with a valid claim digest, no finish state, empty attempts, zero known cost/known status, no previous recovery and the existing valid fresh quote/bounds/history. Generic, legacy non-amended eastus, unclaimed, completed/failed, attempted, unknown/known consumed exposure and malformed/repeated recovery fail without writing. No quote replacement, new reserve, refund or consumed-slot reopening is authorized.

Recovery preserves every original monetary, ID, phase, timestamp, quote/binding, regional-history, ordered hash and cap field. It archives the full prior claimed state, including its digest but **no raw token**, under one `claim_recoveries` audit with fixed reason `pre_dispatch_manifest_docs_only_head_mismatch` and UTC time, plus a validated count 1 marker and SHA256 fingerprint of the complete canonical audit. It atomically invalidates the old digest and returns to unclaimed reserved state. Claim/consume/settle revalidate this audit, its fingerprint, immutable original provenance and the marker together; a marker alone is not authorization. The new legitimate claim must have a digest different from the archived one. If consume wins the race, its durable unknown attempt blocks recovery; if recovery wins, the old token cannot consume immediately or after the new claim. The original global ten-attempt allowance remains. This exception never makes consumed/unknown failure recoverable or refundable.
